Minggu 10: Mesin State (FSM) — Analisis & Desain Sekuensial

Diagram state, tabel state/eksitasi, Mealy vs Moore, detektor sekuens, dan contoh lampu lalu lintas.

🧭 Apa itu FSM?

Rangkaian sekuensial dengan state (keadaan) yang berpindah tiap clock sesuai input. Didesain lewat: diagram state → tabel state → tabel eksitasi FF → persamaan → rangkaian.

🪜 Langkah desain

1) Spesifikasi → 2) diagram state → 3) tabel state → 4) encoding (biner/Gray/one-hot) → 5) tabel eksitasi → 6) K-Map → 7) rangkaian + verifikasi timing.

🥤 Analogi: mesin penjual otomatis

FSM = mesin penjual minuman: punya state (menunggu koin, total Rp3.000, total Rp5.000, mengeluarkan minuman) dan aturan pindah (masukkan Rp2.000 → pindah ke state total baru). Output (mengeluarkan minuman + kembalian) ditentukan state + koin terakhir (Mealy) atau murni state "sudah lunas" (Moore).

Desain FSM = menulis "buku panduan" mesin: daftar semua keadaan, untuk tiap keadaan tulis "jika input X maka pindah ke keadaan Y". Tabel state adalah buku panduan itu; diagram state adalah peta gambarnya. Keduanya sama isinya, beda penyajian.

🧮 Membaca detektor "101" (overlap)

Tiga state artinya "seberapa panjang awalan pola yang sudah kulihat": S0 = belum cocok apa-apa, S1 = baru lihat 1, S2 = baru lihat 10. Di S2 jika masuk 1 → pola lengkap → output 1!

Trik overlap: setelah deteksi, jangan kembali ke S0 melainkan ke S1 — karena 1 terakhir bisa jadi awalan pola berikutnya (mis. aliran 10101 mengandung pola 2×). Tanpa overlap, detektor melewatkan pola kedua. Coba ketik 10101 di simulator dan majukan langkah demi langkah!

⚖️ Mealy vs Moore — kapan pakai apa?

Mealy: output = f(state, input) — cocok untuk detektor sekuens (reaksi langsung). Moore: output = f(state) — cocok untuk controller (traffic light, elevator) karena output stabil per state.

Contoh: detektor "101" ala Mealy butuh 3 state; versi Moore butuh 4 state (output di state akhir).
